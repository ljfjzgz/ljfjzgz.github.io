### 1 引言

#### 1.1 目的和背景

​	目前公司的报价不统一，不同的业务系统下报价的概念、计费逻辑、表现形式不尽相同，比如成本系统，产品系统都有着各自的定义和实现逻辑，缺乏通用性考量，新增一种报价往往都需要个性化定制开发，没有一个统一、通用的标准，比较费时费力，并且代码还不好维护，目前亟需一个统一的、标准的报价系统，以应对公司的业务的快速扩张。

​	在这种背景下，计费引擎应运而生。本文旨在阐述计费引擎报价创建接口的详细说明，为其他系统同步报价到计费引擎提供指引。

#### 1.2 参考文献

计费引擎需求文档：[计费引擎方案文档](https://ljfjzgz.github.io/计费引擎prd/计费引擎PRD.html)

计费引擎UI原型：[万邦速达 - 计费引擎系统](https://ljfjzgz.github.io/计费引擎DEMO.html)

#### 1.3 相关术语

| 术语         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| 单据         | 指业务系统诸如运单、箱子、包裹这样的业务对象。单据类型对应引擎的BusinessItemTypeInfo |
| 维度         | 指单据上面用于匹配的字段，如起始节点，目的节点。维度编码对应引擎的BusinessItemDimension |
| 因子         | 指单据上面用于计算的字段，如长宽高。因子编码对应引擎的BusinessItemFactor |
| 费用项       | 业务发生的费用项。费用项编码对应引擎的BusinessItemTypeInfo   |
| 最小单元报价 | 客户导入的原始报价往往包含多个最小单元报价，计费引擎不关心客户原始的报价，**本文中的报价若无特殊说明，均指最小单元报价** |

##### 2.1.10 UpdateQuotationCalculationMethodRequest

以下四种方式任传一（或多个）

| 字段名               | 数据类型                                   | 是否必传 | 说明       |
| -------------------- | ------------------------------------------ | -------- | ---------- |
| RangeCalculation     | UpdateQuotationRangeCalculationRequest     | 否       | 分段计费   |
| StepCalculation      | UpdateQuotationStepCalculationRequest      | 否       | 累进计费   |
| RatioCalculation     | UpdateQuotationRatioCalculationRequest     | 否       | 比例计费   |
| ConditionCalculation | UpdateQuotationConditionCalculationRequest | 否       | 条件型计费 |

RangeCalculation分段计费的方式最常见，所有的费用=单价*因子，都可以按这种方式传，如果需求是每小时收费2.35元，则传值如下（USE_HOURS是示例因子编码）：

```json
{
    "RangeCalculation": {
        "Sections": [
            {
                "SectionFactor": "USE_HOURS",
                "Begin": 0,
                "IncludeBegin": true,
                "End": null,
                "IncludeEnd": null,
                "FeeFactor": "USE_HOURS",
                "UnitPrice": 2.35,
                "MinValue": null,
                "MaxValue": null
            }
        ]
    }
}
```

#### 2.2批量创建/更新报价接口

业务系统一份报价对应多个最小单元报价，则可以通过此接口全量创建更新报价。不在本接口范围的历史相同ClientQuotationId的报价会做删除操作。

接口地址：/api/quotations/create-by-batch

HttpMethod：POST

.NET SDK：FishChips.CostEngine.Sdk.Definitions.IQuotationService.CreateByBatch

请求参数：CreateQuotationByBatchRequest

##### 2.2.1 CreateQuotationByBatchRequest

| 字段名            | 数据类型                     | 是否必传 | 说明                 |
| ----------------- | ---------------------------- | -------- | -------------------- |
| ClientQuotationId | string                       | 是       | 业务系统报价原始Id   |
| Quotations        | List<CreateQuotationRequest> | 是       | 报价（最小单元）列表 |

CreateQuotationRequest定义见2.1



#### 2.3创建/更新报价便捷(兼容)接口

根据产品需求，若业务系统无法提供【一级、二级、三级业务和单据编码】字段，引擎提供一个便捷接口，用计费模型的编码（提前约定）代替这几个参数。由于计费模型编码不属于报价的一部分，实际上后台也是根据计费模型编码去查询对应的【一级、二级、三级业务和单据编码】，然后调用2.1.1的标准接口。

接口地址：/api/quotations/create-by-charge-model-code

HttpMethod：POST

.NET SDK：FishChips.CostEngine.Sdk.Definitions.IQuotationService.CreateByChargeModelCode

请求参数：CreateQuotationByChargeModelCodeRequest

##### 2.3.1 CreateQuotationByChargeModelCodeRequest

| 字段名          | 数据类型                         | 是否必传 | 说明                                                         |
| --------------- | -------------------------------- | -------- | ------------------------------------------------------------ |
| Id              | string                           | 否       | 成本引擎的Id，可空，不为空则用Id关联已有报价                 |
| ChargeModelCode | string                           | 是       | 计费模型编码，取值来自ChargeModel，如业务系统未动态获取引擎的基础数据，则传值需要提前约定。 |
| ClientInfo      | UpdateQuotationClientInfoRequest | 是       | 业务系统报价信息                                             |
| Content         | UpdateQuotationContentRequest    | 是       | 报价内容                                                     |
