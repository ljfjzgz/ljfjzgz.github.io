# 01 客户赔付

本章按单据生命周期讲客户赔付线的六件事：**录单 → 查单 → 审核 → 改错 → 红冲 → 申诉**。同一个列表页上分布着不同任务的入口，按你要办的事跳到对应小节即可。字段定义见附录 B.1，汇率与申诉等口径见 00-认识系统 §1.3。

---

## 2.1 让赔付数据进来

### 2.1.1 批量导入赔付数据

**什么时候做**：有一批赔付数据需要入系统（日常主要入口）。

**在哪做**：数据导入 → 赔付客户导入。该菜单下有两个入口，**页面完全相同**，区别只在提交后要不要等结果：

| 入口 | 提交后 |
| --- | --- |
| 直接上传 | 同步执行，当场显示成功 / 失败条数 |
| 队列上传 | 转入后台执行，页面不等结果；进度与结果到上传队列页看（见 2.1.2） |

进入页面后，顶部「操作类型」选择**导入新增赔付**（同一页面另有「批量回填申诉」，见 2.6.2）。

**怎么做**：

1. 下载导入模板（列结构固定）；
2. 按模板填写：

| 模板列 | 必填 | 填写要求 |
| --- | --- | --- |
| 处理号 | 是 | 须在 OMS 订单表中存在 |
| 赔付原因 | 是 | 须在赔付原因（客户）配置表中存在（维护方法见附录 A） |
| 赔付币种 | 是 | 标准币种代码，如 USD、CNY、EUR |
| 赔付金额 | 是 | 大于 0，最多 2 位小数 |
| 赔偿标准 | 否 | 最多 100 字符，超长截断 |
| 备注 | 否 | 最多 200 字符，超长截断 |

3. 上传 .xlsx 文件（不超过 10MB），系统解析并校验；
4. 确认导入。

**组合唯一性校验**（按「处理号 + 赔付原因」查历史记录）：

| 历史记录情况 | 结果 | 说明 |
| --- | --- | --- |
| 不存在 | 允许导入 | — |
| 存在且红冲单号为空 | 阻断 | 该订单此原因已有未完结赔付，未被红冲 |
| 存在、已红冲、红冲原因为主动红冲 | 允许导入 | 主动红冲视为撤销原赔付，可重新赔付 |
| 存在、已红冲、红冲原因为申诉红冲 | 阻断 | 申诉红冲为差额冲销，原赔付事实成立，不支持重新导入 |

**做完会怎样**（直接上传；队列上传见 2.1.2）：

- 校验通过的数据**立即创建为赔付单，状态【待审核】**；
- 页面显示导入结果汇总（成功 X 条 / 失败 Y 条），可下载失败提示文档，文档在原上传表数据基础上增加一列「失败原因」，逐行说明失败原因（处理号不存在、原因为空、原因不存在、币种无效、重复导入等）。

**注意**：导入是**逐行校验、部分成功**——通过的行直接建单，失败的行不影响其他行，也不存在「整份回滚」。所以出现「成功 X / 失败 Y」是正常结果，不是导入失败；要处理的是失败文档里的那几行。

### 2.1.2 上传队列：看异步导入的进度与结果

**什么时候做**：用「队列上传」提交过导入，需要知道这批跑到哪一步、成功多少条、哪些行失败。

**在哪做**：数据导入 → 上传队列。**赔付客户导入与尾程索赔导入共用这一页**，两条业务线的队列任务都汇总在这里；页面只显示当前用户自己上传的任务。

**怎么看**：

筛选条件：上传时间（按范围选）、文件名关键字、批次号（系统生成）、状态、类型。

列表按任务一行，其中几列需要知道：

| 列 | 含义 |
| --- | --- |
| 类型 | 这次任务是哪条业务线的哪种操作，如「客户赔付-申诉」「尾程索赔-批量确认金额」 |
| 文件ID | 点「下载原文件」可把那一次上传的 Excel 原样下回来 |
| 总条数 / 完成条数 / 失败条数 | 文件里的行数，以及其中建单成功、校验未通过的行数；失败条数为红色数字，点击可下载失败文件，文件在原上传表数据基础上增加一列「失败原因」，说明该行为什么失败 |

**任务怎么跑起来**：队列上传提交后自动执行，不需要人工启动。

**注意**：失败条数大于 0，说明这批数据是**逐行校验、部分成功**，与直接上传看到的「成功 X / 失败 Y」是一回事——已建单的部分不用管，要处理的是失败的那些行。

### 2.1.3 单条新增赔付

**什么时候做**：只有一两笔数据，不值得走导入。

**在哪做**：列表页顶部【新增】。

**怎么做**：填写与导入模板相同的字段（处理号、赔付原因、赔付币种、赔付金额、赔偿标准、备注），处理号须存在于 OMS 订单表，赔付原因与币种下拉选择；提交时执行全字段校验与组合唯一性校验（规则同上表）。

**做完会怎样**：创建为【待审核】，返回列表并提示新增成功。赔付类型由赔付原因自动带出（异常赔付 / KPI 扣罚），不需要填写。

## 2.2 找到要处理的单子：查询、筛选与导出

**什么时候做**：每次处理赔付单之前——先从全量数据里圈出你要处理的那批。

**在哪做**：小包客户赔付列表页。

**怎么做**：

列表支持按以下字段筛选（字段含义见附录 B.1）：

| 类别       | 可筛选字段                                               |
| ---------- | -------------------------------------------------------- |
| 单据标识   | 处理号（支持批量查询：一次粘贴多个处理号）、单据类型     |
| 订单信息   | 客户代码、客单号、跟踪号、目的国、产品代码、提单号、箱号 |
| 类型与状态 | 赔付类型、赔付状态、申诉状态、轨迹状态                   |
| 时间       | 揽收时间、审核时间、完结时间、申诉时间、创建时间         |

**做完会怎样**：

- 列表上方实时显示当前查询条件下的**赔付原币金额分币种汇总**（如「CNY 120,500.00 ; GBP 1,230.00 ; USD 3,450.00」），只做原币分币种合计、不折算 CNY，且不随翻页变化；
- 点【导出】下载当前筛选结果为 Excel。

**注意**：本页的【根据查询条件批量审核】【根据查询条件批量红冲】**作用于查询条件命中的全部记录，不是勾选项**。查询条件就是批量操作的作用范围——操作前先核对汇总条数与预期是否一致，条件设错会打错整批。

## 2.3 审核赔付单

### 2.3.1 单条审核

**什么时候做**：单据状态为【待审核】时（行内出现【审核】按钮）。

**在哪做**：列表行内【审核】。

**怎么做**：弹窗上方只读展示处理号、客户代码、赔付类型（帮助判断是否走申诉分支）、赔付金额；填写：

| 字段 | 必填 | 要求 |
| --- | --- | --- |
| 审核结果 | 是 | 通过 / 驳回 |
| 审核原因 | 条件 | 驳回时必填，至少 5 个字符 |

**做完会怎样**：

| 审核结果 | 状态变化与系统动作 |
| --- | --- |
| 通过 | 状态变为【已审核】；记录审核时间、审核人；系统异步回填财务 ID；若为 KPI 扣罚类型，申诉状态自动置为【申诉中】；该笔赔付同时写入订单赔付索赔底表 |
| 驳回 | 状态变为【已驳回】；记录审核原因，可编辑后重新提交 |

> 推送财务为一期占位（见 00 §1.1）：系统回填固定 ID 后单据自动流转至【已完结】，实际由人工导入财务系统。

### 2.3.2 按查询条件批量审核

**什么时候做**：当前筛选结果整批都是待审核单据，需要一次性处理。

**在哪做**：列表顶部【根据查询条件批量审核】。

**怎么做**：

1. 先设置查询条件（条件即作用范围，见 2.2 注意）；
2. 点击按钮，系统逐条校验：**当前筛选结果必须全部为【待审核】**，存在非待审核记录时阻断并提示「当前筛选条件下存在 N 条非待审核的记录，汇总数与实际可审核数不一致。请确认查询条件后重新操作。」；
3. 校验全部通过后弹出确认窗，展示校验通过的记录数、筛选条件摘要、审核结果（通过/驳回）单选、驳回原因（驳回时必填）；
4. 确认后批量执行，处理逻辑与单条审核一致。

## 2.4 录错了怎么办：编辑与删除

**什么时候做**：正常赔付单状态为【待审核】或【已驳回】，数据需要修改或作废。

**在哪做**：列表行内【编辑】/【删除】。

**怎么做**：

- **编辑**：页面同新增页，**处理号不可修改**；保存时执行全字段校验与组合唯一性校验；
- **删除**：二次确认后物理删除。

**做完会怎样**：

- 编辑保存后单据**状态重置为【待审核】**，需重新审核——哪怕只改一个备注也一样；
- 删除后单据从列表消失。

**注意**：已审核及之后的状态（已审核 / 已完结）不可编辑、不可删除，只能走红冲（见 2.5）。红冲单的编辑删除规则不同，见 2.5.3。

---

## 2.5 冲掉已完结的赔付：红冲

红冲用于把一张已生效的赔付单对冲掉。客户赔付有两种红冲：

| 红冲类型 | 触发方式 | 审核方式 |
| --- | --- | --- |
| 主动红冲 | 人工单条或按查询条件批量发起 | 需人工审核 |
| 申诉红冲 | KPI 扣罚申诉成功时系统自动生成（差额） | 自动审核通过 |

本小节讲主动红冲；申诉红冲随 2.6 的申诉操作自动发生。

### 2.5.1 单条主动红冲

**什么时候做**：数据录错（金额、币种、处理号等）、单据完结后发现错误、业务取消赔付；且同时满足以下四条（任一不满足时系统阻断并提示）：

- 单据类型 = 正常赔付
- 赔付状态 = 已完结
- 红冲单号 = 空
- 赔付类型 = 异常赔付；或 赔付类型 = KPI 扣罚 且 申诉状态 = 申诉失败

**在哪做**：列表行内【红冲】。

**怎么做**：弹窗只读展示处理号、赔付原因、赔付金额；可填红冲说明（最多 200 字符）；确认发起。

**做完会怎样**：

- 系统生成红冲单：处理号与原单一致，单据类型为「红冲赔付」，金额为原单相反数，状态【待审核】；
- **立即回填红冲单号到原赔付单**（不论红冲单后续审核是否通过）；
- 列表提示红冲单生成成功，需前往审核；
- 红冲单审核通过后回填固定财务 ID（一期占位），状态流转至【已完结】；驳回则为【已驳回】。

**注意**：上面说的「立即回填」发生在**发起的那一刻**，不是等红冲单审核通过——所以红冲单被驳回时，原单的红冲单号已经回填（单据本身仍为【已完结】），不能再发起一次红冲。出路只有两条：删除红冲单（清空红冲单号，见 2.5.3）后重来，或把红冲单改后重新提交审核。

### 2.5.2 按查询条件批量红冲

**什么时候做**：一批已完结赔付单需要同时冲掉。

**在哪做**：列表顶部【根据查询条件批量红冲】。

**怎么做**：系统按下列顺序逐条校验，一条记录命中第一个不满足项即停止后续检查（每条不合规记录只计一次）：

| 顺序 | 校验项 | 阻断提示 |
| --- | --- | --- |
| 1 | 单据类型 = 正常赔付 | 当前筛选条件下存在 N 条【红冲赔付】单据，无法根据查询条件批量红冲 |
| 2 | 赔付状态 = 已完结 | 当前筛选条件下存在 N 条非【已完结】状态的记录 |
| 3 | 红冲单号为空 | 当前筛选条件下存在 N 条已红冲的记录 |
| 4 | KPI 扣罚需申诉失败 | 当前筛选条件下存在 N 条 KPI 扣罚类型且申诉状态非【申诉失败】的记录 |

弹窗会列出所有 N>0 的校验项及数量，任一项不通过即整体阻断，调整条件后重新操作；全部通过则确认后批量生成红冲单（生成规则同单条，**无红冲说明输入**），完成后提示批量红冲成功。

### 2.5.3 删除红冲单

**什么时候做**：红冲单状态为【待审核】或【已驳回】时（如误发起红冲）。

**在哪做**：红冲单所在行的【删除】（仅红冲赔付单据显示）。

**做完会怎样**：二次确认后物理删除，并**清空原赔付单的红冲单号**，原单可重新发起红冲。

**注意**：红冲单【已审核】【已完结】状态不可删除。

### 2.5.4 红冲之后重新赔付

红冲单发起、红冲单号回填后即可重新赔付，不必等红冲单审核通过：重新导入或新增，使用**原处理号与原赔付原因**（因红冲单号已有值，唯一性校验放行），新单生成新的单据 ID，与原红冲单无关联，走正常审核流程。

**注意**：重导前先确认红冲单已审核通过。红冲单还在【待审核】时重导，若之后红冲被驳回，原赔付单与新赔付单会同时生效，形成重复赔付。

## 2.6 KPI 扣罚的申诉

仅**赔付类型 = KPI 扣罚**的单据有申诉流程。申诉是独立分支，不改变赔付状态。

### 2.6.1 单条回填申诉

**什么时候做**：同时满足 —— 赔付类型 = KPI 扣罚、申诉状态 = 【申诉中】、赔付状态 = 【已完结】。未完结时点击会提示「财务未返回ID，请等待赔付完结后再回填申诉」。

**在哪做**：列表行内【回填申诉】。

**怎么做**：弹窗只读展示处理号、客户代码、赔付类型、赔付金额；填写：

| 字段 | 必填 | 要求 |
| --- | --- | --- |
| 申诉结果 | 是 | 申诉成功 / 申诉失败 |
| 最终赔付原币金额 | 条件 | 仅申诉成功时必填；只填数字，币种自动取赔付金额币种，金额应 ≤ 赔付金额 |
| 申诉结果说明 | 条件 | 申诉失败时必填，至少 5 个字符 |

**做完会怎样**：

- **申诉成功**：记录最终赔付原币金额；系统计算：

  | 计算项 | 规则 |
  | --- | --- |
  | 申诉金额原币 | 赔付金额原币 − 最终赔付原币金额 |
  | 申诉汇率、申诉金额 CNY | 申诉汇率取原赔付单的赔付汇率（申诉时点不重算）；申诉金额 CNY = 申诉金额原币 × 申诉汇率 |
  | 申诉红冲单 | 金额 = −申诉金额差额（差额冲销，非全额），汇率复制原赔付单汇率，自动审核通过并回填财务 ID |

- **申诉失败**：申诉状态置为【申诉失败】，记录申诉结果说明，**不生成红冲单**，申诉流程结束；赔付单按原流程等待完结。

**注意**：申诉成功生成的申诉红冲单**不经过人工审核**——系统算出差额后直接自动审核通过并回填财务 ID。提交即生效，申诉结果回填后不能再改；填之前先核对最终赔付金额，它直接决定冲回多少。

**演算示例**（KPI 扣罚单，原赔付金额 USD 100）：

| 步骤 | 发生的事 | 金额 |
| --- | --- | --- |
| ① 导入并审核通过 | 赔付成立、计入成本；系统回填固定财务 ID，实际扣款由人工导入财务系统 | 赔付 USD 100 |
| ② 回填申诉成功，最终赔付金额填 30 | 系统计算申诉金额 = 100 − 30 | 申诉 USD 70 |
| ③ 自动生成申诉红冲单 | 金额取负，自动审核通过 | 红冲 −USD 70 |
| ④ 结果 | 公司实际承担 | USD 30 |

### 2.6.2 批量回填申诉

**什么时候做**：一批 KPI 扣罚单的申诉结果已经拿到，需要一次回填。

**在哪做**：数据导入 → 赔付客户导入 → 直接上传或队列上传（两个入口页面相同，差别见 2.1.1），「操作类型」选择**批量回填申诉**。

**怎么做**：按模板填写后上传：

| 模板列 | 必填 | 要求 |
| --- | --- | --- |
| 处理号 | 是 | 须在 OMS 订单表中存在 |
| 赔付原因 | 是 | 须在配置表中存在，与处理号组成复合匹配键 |
| 申诉结果 | 是 | 成功 / 失败 |
| 最终赔付原币金额 | 条件 | 仅申诉成功时必填，只填数字，币种自动取原赔付币种，金额应 ≤ 原赔付金额 |
| 申诉说明 | 否 | 最多 200 字符，申诉失败时展示 |

系统按两步校验：

1. **唯一匹配**：按「处理号 + 赔付原因 + 红冲单号为空」查找——0 条失败（未找到未红冲的赔付记录）；1 条进入第 2 步；≥2 条标记失败（数据异常）；
2. **前置条件**：赔付类型须为 KPI 扣罚、赔付状态须为已完结、申诉状态须为申诉中、红冲单号须为空、最终赔付金额不得大于原赔付金额，任一不满足即该行失败并给出原因。
