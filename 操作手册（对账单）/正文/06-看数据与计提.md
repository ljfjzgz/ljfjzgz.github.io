# 06 看数据与计提

> 本章讲对账结果怎么变成可用的数据：先看结算进度（应付账单统计表），再出计提数据（滚动计提表 + 确认计提）。两处取数口径不同——统计表看实时最新状态，计提表看固化结果。

---

## 6.1 应付账单统计表：看结算进度

**什么时候用**：每月扫描结算进度、跟进还没结的账、做资金计划。

**在哪看**：应付账单统计表页面。

**按什么统计**：四个维度——**供应商 + 账单类型 + 业务期间 + 币种**，缺一不可。业务期间取单据时间所属整月。

**三个金额怎么分**：这张表的核心是回答"这笔成本现在结算到哪一步了"。

**总金额（计算）= 已结算金额 + 未结算金额 + 不结算金额**，三者互斥且全覆盖，等式永远成立。

| 指标 | 判定条件 | 业务含义 |
| --- | --- | --- |
| 已结算 | 明细状态=已完成 且 结算策略非空 且 不是清账 | 已定策略并完成对账，转入待付款（付款由账单管理执行） |
| 未结算 | 明细状态 ≠ 已完成 | 还没走到终态，含：账单没上传、策略没选、策略选了但没完成对账、作废了但还没完成对账 |
| 不结算 | 明细状态=已完成 且 结算策略=清账 | 清账是"不结算"的唯一来源 |

**看完会怎样**：默认按未结算金额倒序，未结算多的排前面——直接就是需要跟进的清单。筛业务期间默认最近一个完整月（如 7 月打开默认 2026-06）。

**注意**：

- **它是实时的，不是快照**。同一期间今天看和明天看数字可能不同，因为底表状态在变。要留档就导出。
- 金额取的是**最新计算金额**，不是对账时固化的快照——所以这张表反映的是"按现在系统算的成本，还有多少钱没结"，不是"当初对账认定的金额"。
- 最新计算金额为空的按 0 处理，保证等式成立。

## 6.2 滚动计提表：三类金额从哪来

**这张表干什么**：每月会计期末出成本计提入账数据，给金蝶用。

**核心公式**：

```
当期成本计提 = 红冲上期暂估 + 当期确认金额 + 各期暂估合计
```

**三个时间概念先分清**，否则看不懂表：

| 概念 | 是什么 | 用在哪 |
| --- | --- | --- |
| 计提期间 | 本次要做账的目标月份，由用户选择 | 选择参数、筛选条件 |
| 完成对账时间所在月 | 这条成本哪天完成对账的 | 判断它进"确认"还是"暂估" |
| 业务期间 | 单据时间所属整月，即这笔业务实际发生在哪个月 | 判断往期挂账该不该在本期提 |

**三类行**：

| 计提类型 | 从哪取 | 金额取什么 |
| --- | --- | --- |
| 红冲 | 上一期（M-1）计提确认表里计提类型=暂估的固化行 | 原金额 × (−1)，计提期间改为本期，其余维度不变 |
| 确认 | 对账明细底表里 完成对账时间所在月 = 本期 的记录 | 付款金额 |
| 暂估 | 底表里 完成对账时间所在月 > 本期或为空，且 业务期间 ≤ 本期 的记录 | 最新计算金额（空按 0 算） |

一句话理解：**本期结算掉的走确认、本期还没结算的走暂估、上期提过的暂估本期先冲回来再重新提**。

**四条判定线**（任何一条底表记录必落其中之一）：

| 场景 | 完成对账时间所在月 | 业务期间 | 归属 |
| --- | --- | --- | --- |
| ① | = 本期 | 任意 | 确认 |
| ② | > 本期 或 为空 | ≤ 本期 | 暂估 |
| ③ | < 本期 | 任意 | 不进入本期（早前提过了） |
| ④ | > 本期 或 为空 | > 本期 | 不进入本期（业务还没发生到） |

**注意**：

- **红冲只冲上一期**。M-1 没计提过就没有红冲行。
- **暂估按最新计算金额**，不是快照——所以同一笔业务在不同月份暂估的金额会变，这是设计如此，反映成本的真实变动。
- **全表不做跨币种折算**，不同币种分行，各自合计。
- **清账和不支付没有特殊分支**，按上面四条正常归入。付款金额为 0 的落进①就是 0，不影响合计；落进②就按最新计算金额参与暂估。
- **这张表只做展示**，财务导出 Excel 后自行筛选透视入账。

## 6.3 确认计提

**什么时候做**：会计期末，对**要计提的月份**执行一次。

**在哪做**：滚动计提表页——先用「计提期间」下拉选月份，再点「确认计提」。

**前置条件**：该计提期间**尚未计提过**。已计提过的期间不能再执行计提。

**怎么做**：先选月份，再点计提。

1. **选计提月份**：页顶「计提期间」下拉选要做账的那个月。选中的月份就是本次计提的目标期间，计提的是**这个月**的成本。
2. **点「确认计提」**：弹窗里的计提期间自动带入刚才选中的月份，并写明——确认后将固化当期计提数据、操作不可逆；已计提期间不可撤销、不可重新计提；如需调整金额，请在金蝶系统通过冲销处理。
3. **确认后系统执行**：按 6.2 的规则从底表取数、判定计提类型 → 聚合生成红冲 / 确认 / 暂估三类行 → 全量写入计提确认表**固化**。

**做完会怎样**：数据与底表解耦。之后查询滚动计提表读的是这张固化表，不再实时取底表，所以历史查询结果可以重现。未计提的期间查不到数据，会提示「尚未计提，请先执行计提确认」。

**注意**：

- **这是本需求里最不可逆的动作之一**。计提期间一旦固化就与底表永久脱钩，之后底表怎么变都不影响已计提数据。
- **确认前必做三件事**：核对计提期间对不对、查询这张期间的暂估 / 确认是否合理、核对金额合计。确认完发现问题只能去金蝶冲销。
