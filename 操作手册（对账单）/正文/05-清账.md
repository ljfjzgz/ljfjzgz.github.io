# 05 清账

> 清账是一条旁路：把超过半年仍未结算的记录，用系统自动跑完的对账流程一次性闭环。本章只讲清账页面上的操作，跑起来之后的内部动作按 03、04 章的口径理解。

---

## 5.1 什么样的记录能清账

**清账要解决的事**：有些成本单据挂了很久，供应商一直没出账或账期早就过了，这笔钱既结不掉也退不掉。清账就是让系统按当前计算成本把这些记录"自己跟自己对一遍"，落成付款金额为 0 的已完成记录，把账结清。

**什么记录能进来**：必须同时满足四条，缺一条都不会出现在清账列表里。

| 条件 | 含义 |
| --- | --- |
| 作废标记 = 正常 | 作废记录不参与任何统计与清账 |
| 明细状态 = 初始 | 还没被任何对账单占用、没进入过对账流程 |
| 最新计算金额非空 | 系统有算过钱（值为 0 也算有值，可以清） |
| 单据时间距今 ≥ 180 天 | 超过半年未结算 |

**页面怎么呈现**：列表上方有一条常驻提示条，把四个条件写在页面上（不提供关闭）。筛选条件的「单据时间」**默认只取刚过 180 天的一小段（约一个月）**，不是全部历史——打开后先看到的是刚够条件、最该处理的那批，条数会比实际可清账的少；要看清全量，把起始日期往前放宽再查。

**注意**：

- **已被对账单占用的记录不会出现**。明细状态只要不是【初始】，就进不了这个页面，所以不会和正常对账抢数据。
- **最新计算金额为空的不出现**。系统没算过钱，就没法生成一条账单金额。

## 5.2 勾选清账 与 按查询条件清账

**两个按钮，一个区别：处理范围。**

| 对比项 | 清账（勾选版） | 根据查询条件清账（全量版） |
| --- | --- | --- |
| 处理范围 | 手动勾选的那几条 | 当前查询条件下的**全部结果** |
| 前置条件 | 至少勾 1 条 | 查询结果至少 1 条 |
| 适用场景 | 小范围、精准指定（如审批通过的那批） | 大范围整批清 |

**权限是页面级的**：清账按页面控权，不单独给按钮授权——能进这个页面，两个按钮都能用；看不到清账菜单，说明没有该页面的访问权限。

**注意**：

- **「根据查询条件清账」的作用域是查询结果，不是勾选项**。条件设宽了会清掉一整批——操作前先把查询条件收紧，并核对确认框里的条数。
- 两个按钮除处理范围外，后续步骤完全一致（分组、字段取值、弹窗都一样）。

## 5.3 填会计期间与账单时间范围并提交

**怎么做**：点任一清账按钮 → 弹二次确认框，框里要核对和填写这些内容：

| 内容 | 说明 |
| --- | --- |
| 分组情况 | 按「供应商 + 币种 + 账单类型」共多少个唯一组合，也就是最终会生成几张账单 |
| 各组合明细 | 每个组合多少条记录、最新计算金额合计多少（分币种展示，不折算加总） |
| 会计期间（必填） | 月份选择，默认当前月，可改；**本批所有清账账单共用** |
| 账单时间范围（必填） | 日期范围，默认取本批记录中最早 ~ 最晚的单据时间，可改；**本批所有清账账单共用** |

**做完会怎样**：提交成功后按分组生成对账单并自动跑完整个对账流程，弹出结果：「清账已完成！本次共处理 X 张清账账单，涉及 Y 条记录。」（X = 唯一组合数，Y = 处理条数）

**注意**：

- **先核对 X 和 Y**。X 是本次将生成的账单张数、Y 是清掉的记录条数，和预期不一致就取消，回去收紧条件。
- 会计期间默认当月不代表就该用当月。清的是往期挂账，期间要按实际做账口径选。
- 会计期间和账单时间范围是**整批共用**的，一批里混了不同期间就别一次清，分批来。

---

## 5.4 清完会发生什么

点击确认后，系统一次性做完这些事：

| 步骤 | 系统做什么 |
| --- | --- |
| 1 生成对账单 | 按「供应商 + 币种 + 账单类型」每个唯一组合生成一张；账单明细按「系统ID + 费用项 + 最新计算金额」逐条展开；账单金额取点清账那一刻的最新计算金额；账单日期取当日 |
| 2 自动开始对账 | 写对账单ID、账单金额，截取快照计算金额，明细状态→待处理 |
| 3 跳过差异判定 | 清账没有供应商账单文件可比，账单金额就是系统金额，判定无意义，所以不生成对比参数、不判差异类型 |
| 4 自动完成对账 | 写入差异类型=清账、结算策略=清账、付款金额=0、完成对账时间，明细状态→已完成 |
| 5 生成账单管理数据 | 按主流程规则 1:1 生成，各费用项金额取付款金额（清账为 0）；生成后由账单管理侧自动审核完成，并把实际成本同步回单据表 |

**做完之后**：这些记录的明细状态变成已完成，不再满足清账页的查询条件，所以**不会再出现在清账列表里**。

**注意**：

- **清账不可逆**。账单一旦生成就完成对账，不能删除、不能撤销。
- **整批是一个事务**。中途失败全部回滚——已生成的对账单删除、底表恢复未占用，可改完再提交。
- **账单金额和快照可能对不上**，这是正常的：账单金额取的是点按钮时的值，快照是系统随后截的，时间差内成本可能变过。因为清账跳过差异判定，这个不一致不影响任何结果。
- **清账不走差异类型带策略的逻辑**。差异类型、结算策略、付款金额三者都是系统在完成对账时直接写死的，不需要预先绑定策略。
