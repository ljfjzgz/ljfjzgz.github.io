# 滚动计提表

## 一、功能概述

### 1.1 业务背景

滚动计提表用于每月会计期末，出具当期成本计提入账数据。业务流程分两步：

1. **计提确认**：财务选择计提期间，系统从对账明细底表按判定逻辑取数（含红冲/确认/暂估三类行），聚合后固化写入计提确认表，**不可逆**
2. **报表查询**：查询时直接读取计提确认表已固化的数据，不再从底表实时取数。未计提的期间不返回数据，提示"尚未计提，请先执行计提确认"

> **时间说明**：会计实务中通常是 N 月做 N-1 月的账。例如 7 月操作，计提期间 = 2026-06（做 6 月账）。文档中"计提期间"指会计上的目标月份，不等于实际操作的日历月份。
>
> **数据固化原则**：计提确认后数据与底表解耦，后续查询直接读取固化数据，历史查询结果可重现。

### 1.2 核心公式

```
当期成本计提 = 红冲上期暂估 + 当期确认金额 + 各期暂估合计（当期入账金额）
```

- **红冲上期暂估**：仅当上一期（M-1）已计提确认时产生。读取M-1期计提确认表中`计提类型=暂估`的固化行，金额×(-1)，计提期间改为M，其余维度与原暂估行完全一致。M-1未计提时无红冲数据
- **当期确认金额**：计提确认时从底表取`完成对账时间`所在月 = 计提期间 的记录，按`付款金额`聚合固化
- **各期暂估合计**：计提确认时从底表取`完成对账时间`所在月 > 计提期间 或 `完成对账时间`为空 且 `业务期间 ≤ 计提期间` 的记录（含当期和往期未结算），按`最新计算金额`聚合固化

### 1.3 三个时间概念

| 概念 | 定义 | 用途 |
| ---- | ---- | ---- |
| **计提期间** | 目标会计月（做账月份），用户选择参数 | 计提确认的目标期间；查询的筛选条件 |
| **完成对账时间所在月** | 对账明细底表字段值（完成对账时写入） | 计提确认时判断记录归入确认还是暂估 |
| **业务期间** | = `单据时间`所属整月（取值规则见2.2） | 计提确认时暂估行的准入过滤条件；查询时展示当期/往期归属 |

## 二、计提数据处理

本章描述**计提确认时**从对账明细底表取数、判定、聚合并固化写入计提确认表的完整逻辑。查询时不执行本章逻辑，仅读取已固化的计提确认表数据（详见第三章）。

### 2.1 数据来源

| 计提类型 | 数据来源 | 说明 |
| -------- | -------- | ---- |
| **红冲** | M-1期计提确认表（固化数据） | 取M-1期`计提类型=暂估`的固化行，金额×(-1)，计提期间改为M，其余维度不变 |
| **确认** | 对账明细底表 | `完成对账时间`所在月 = M 的记录，取`付款金额` |
| **暂估** | 对账明细底表 | `完成对账时间`所在月 > M 或为空，且`业务期间 ≤ M`的记录，取`最新计算金额` |

> **全局过滤**：从底表取数的确认/暂估行均**排除作废追加记录 R'**（即排除 `作废标记 = 作废` 且 `明细状态 = 已完成` 的记录，R' 仅用于底表查询追溯，不参与计提）。红冲行来源为M-1期计提确认表固化数据，不涉及作废过滤。
>
> 说明：对账中阶段被标记作废但未完成对账的记录（`作废标记 = 作废` 且 `明细状态 ≠ 已完成`，即原占用记录 R）**仍参与计提判定**——按其 `完成对账时间` 与 `业务期间` 落入4个场景之一（典型为场景②暂估），避免对账期间作废导致成本数据"消失"；完成对账时 R 被释放回池（作废标记置正常、明细状态置空），自然转入后续期间的暂估或确认。

### 2.2 关键取值规则

**1）单据时间取值规则**（用于计算业务期间）：

- **非尾程类**（国内转运 / 内地空运 / 香港空运 / 空运卡转 / 国外清关 / 国外转运）→ 运单**发运时间**，发运时间为空则取运单**创建时间**
- **尾程类**（尾程派送）→ 扣费时间（无则取出库时间，仍没有则取创建时间）
- **孤儿账单** → 底表**创建时间**
- **红冲行** → 沿用M-1期计提确认表原暂估行的`业务期间`字段值（不重新计算）

**2）供应商取值规则**：

- 确认/暂估行：统一取底表`供应商编码`、`供应商名称`字段
- 红冲行：沿用M-1期计提确认表原暂估行的`供应商编码`、`供应商名称`字段值

**3）币种与金额口径**：

- 全表金额均不做跨币种折算或累加
- 暂估取`最新计算金额`（空值视为0参与计算），计提确认时取当前时刻值固化
- 红冲金额 = M-1期固化暂估金额 × (-1)，为静态值
- 确认取`付款金额`，`完成对账时间`写入后为静态值不再变化

### 2.3 计提类型判定规则

#### 2.3.1 计提类型定义

计提确认时，系统从底表取数并判定每条记录归入以下三种计提类型之一：

| 计提类型 | 范围条件（全部满足） | 取值字段 / 取数规则 |
| -------- | -------------------------------------------------------------------------- | ------------------------------------------------------- |
| **红冲** | M-1期已计提确认；取M-1期计提确认表中`计提类型=暂估`的固化行 | M-1期原暂估行`金额` × (-1)；计提期间改为M，其余维度不变 |
| **确认** | `完成对账时间`所在月 = M | `付款金额` |
| **暂估** | (`完成对账时间`所在月 > M **或** `完成对账时间`为空) **且** `业务期间 ≤ M` | `最新计算金额`（空值视为0参与计算） |

> 确认/暂估行按底表两层过滤：**第一层按`完成对账时间`**：`完成对账时间所在月= M`→确认；`完成对账时间所在月< M`→硬过滤不进入M期计提（场景③）；`完成对账时间所在月> M`或为空→进入暂估候选池。**第二层按`业务期间`**：暂估候选中`≤ M`→暂估（场景②）；`> M`→不进入M期计提（场景④）。

#### 2.3.2 全场景覆盖矩阵（所有组合无遗漏）

**红冲行来源为计提确认表，不参与下表的底表4场景判定，按2.3.1红冲规则独立准入。**

对对账明细底表任一条记录（已按全局过滤规则排除作废追加记录 R'），按「`完成对账时间`所在月 × `业务期间`」可落到以下 4 种场景之一，覆盖所有可能：

| 场景 | `完成对账时间`所在月 | `业务期间`（= `单据时间`整月） | M 期归属 | 业务含义 |
| ---- | -------------------- | ------------------------------ | -------- | -------- |
| ① | `所在月= M` | 任意值（通常 ≤ M） | **确认** | M 期内完成结算的记录，按实际付款金额入账 |
| ② | `所在月> M` **或** `为空` | `≤ M` | **暂估** | 业务发生在 M 期或之前、截至 M 期末仍未完成对账结算，按最新计算金额暂估入账 |
| ③ | `所在月< M` | 任意值 | **不进入 M 期** | 已在 M 之前的某个期间计提确认，无需再处理 |
| ④ | `所在月> M` **或** `为空` | `> M` | **不进入 M 期** | 业务发生时间（单据时间）在 M 之后，当期不应预提 |

> **清账 / 不支付**：无特殊分支，按上表 4 场景正常归入即可。因`付款金额 = 0`，归入场景①确认时金额为 0，不影响合计；归入场景②时参与暂估（真实还原历史状态）。
>
> **判定互斥性**：红冲/确认/暂估三类行互斥不重复——①红冲行来源独立为M-1期计提确认表，与底表确认/暂估行无交叉；②确认（场景①）与暂估（场景②）在底表4场景矩阵中互斥（`完成对账时间`所在月=M 归确认，`完成对账时间`所在月>M 或空归暂估，两者不会同时满足）；不进入M期计提的场景③④自然排除。

### 2.4 固化规则

计提确认时，系统按上述判定逻辑从底表取数，按 **7 个维度聚合**后写入计提确认表固化：

| 聚合维度 | 说明 |
| -------- | ---- |
| 计提期间 | 用户选择的目标会计月（YYYY-MM） |
| 供应商编码 | 红冲→沿用M-1期原暂估行；确认/暂估→底表`供应商编码` |
| 供应商名称 | 红冲→沿用M-1期原暂估行；确认/暂估→底表`供应商名称` |
| 账单类型 | 红冲→沿用M-1期原暂估行；确认/暂估→底表`账单类型`（7个枚举：国内转运 / 内地空运 / 香港空运 / 空运卡转 / 国外清关 / 国外转运 / 尾程派送） |
| 计提类型 | `红冲` / `确认` / `暂估` |
| 业务期间 | 红冲→沿用M-1期原暂估行；确认/暂估→`单据时间`所属整月（YYYY-MM） |
| 费用项 | 红冲→沿用M-1期原暂估行；确认/暂估→底表`费用项`（系统固定枚举，与账单类型为父子关系） |
| 币种 | 红冲→M-1期计提确认表`币种`；确认/暂估→底表`币种`（不同币种分行，不做跨币种折算或累加） |
| **金额（聚合值）** | 计提类型=红冲 → M-1期固化暂估金额×(-1)；计提类型=确认 → `付款金额`合计；计提类型=暂估 → `最新计算金额`合计（空值视为0） |

> 前 8 行为 GROUP BY 维度（7个维度，供应商编码/名称合为一个维度），第 9 行为聚合值。三类行（红冲/确认/暂估）均按聚合结果固化。

### 2.5 计提确认操作

点击"确认计提"后，系统执行以下流程：

1. 按2.1~2.3逻辑从底表取数并判定计提类型
2. 按2.4规则聚合生成红冲/确认/暂估三类行
3. 全量写入计提确认表固化，固化后数据与底表解耦

- **触发条件**：计提期间已选择 **且** 该计提期间尚未计提过
- **计提期间带入**：弹窗中的计提期间自动带出查询条件中选择的期间
- **二次确认**：点击按钮后弹出确认对话框，提示：
  ```
  ⚠️ 确认后将固化当期计提数据，操作不可逆！
  - 已计提期间不可撤销、不可重新计提
  - 如需调整金额，请在金蝶系统通过冲销处理
  - 请仔细核对数据后谨慎操作
  ```
  对话框提供"确认"和"取消"按钮，点击"确认"执行固化操作，点击"取消"关闭对话框不执行任何操作
- **不可逆性**：已计提期间不可撤销、不可重新计提。如需调整金额，由财务在金蝶系统通过冲销处理，本系统不支持此操作

## 三、报表查询

本章描述查询时的数据来源、筛选条件、操作按钮和报表展示规则。查询时直接读取计提确认表已固化的数据，不执行第二章的判定逻辑。

### 3.1 数据来源

查询统一读取**计提确认表**已固化的数据（含红冲/确认/暂估三类行）。所有字段均为计提确认时刻的固化值，不随底表数据变化。

### 3.2 统计维度

查询时按2.4固化的7个维度+金额展示（详见2.4固化规则表）。业务期间与计提期间的大小关系决定当期/往期归属：=计提期间→当期；<计提期间→往期。

### 3.3 筛选条件

| 字段名称 | 类型 | 必填 | 说明 |
| -------- | ---- | ---- | ---- |
| 计提期间 | 下拉选择（月份枚举） | **是** | 进入页面时默认赋值为当前系统时间的上一月份（会计常规），支持选择历史期间 |
| 供应商 | 下拉选择（按编码+名称匹配） | 否 | 按供应商维度筛选 |
| 账单类型 | 下拉选择 | 否 | 按账单类型筛选 |
| 费用项 | 下拉多选 | 否 | 按费用项筛选 |
| 币种 | 下拉选择 | 否 | 按币种筛选 |

### 3.4 操作按钮

| 按钮 | 功能 | 前置条件 |
| ---- | ---- | -------- |
| 查询 | 根据筛选条件查询计提确认表已固化的数据。未计提期间提示"尚未计提，请先执行计提确认" | 计提期间必选 |
| 重置 | 清空筛选条件 | 无 |
| 导出 | 导出当前报表（Excel） | 已有查询结果 |
| 确认计提 | 对当前计提期间执行计提确认，从底表取数并固化写入计提确认表（详见2.5） | 计提期间已选择 **且** 该期间尚未计提过 |

### 3.5 报表展示

按3.2统计维度展示，9列扁平结构直出给财务（前8列为维度，第9列为金额），财务自行筛选透视按需要维度入账。
