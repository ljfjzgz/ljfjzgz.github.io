## 数据创建与关联规则

### 一、核心模型

底表以 `供应商编码 + 系统ID + 费用项 + 币种` 为主键维度，按供应商隔离。同一维度**可存在多条记录**。记录角色由**创建顺序**决定，系统不维护任何来源标记：

- **最早创建的那条**：成本承载记录。`最新计算金额` 按主键唯一，只写在这条记录上，由单据表成本更新实时同步
- **后创建的追加记录**：开始对账时最早记录已被占用、或主键下无记录匹配不到成本时新增。不承载系统计算成本（自身 `最新计算金额` 为空）

> 边界情形：最早记录也可能由账单创建（开始对账时主键下无任何记录，见第四节）。此时它暂无最新计算金额，待后续单据更新写入后自然承接成本承载角色。

**不变量**（任何时刻成立）：

1. `最新计算金额` 按主键唯一，挂在当前最早创建的记录上
2. 维度一旦被账单占用，成本就跟着账单走，不会出现"账单在、成本却飘在外面"的情况
3. 维度下所有记录的明细状态均为空时，成本挂在最早记录上，可被新账单直接占用

### 二、触发场景

两个外部事件触发底表数据变更：

| 触发源         | 触发时机                     | 对底表的影响                                                                 |
| -------------- | ---------------------------- | ---------------------------------------------------------------------------- |
| 单据表成本更新 | 单据表某单据的费用项成本变更 | 按主键同步**最新计算金额**到最早创建的记录；主键下无记录则新建（详见第三节） |
| 开始对账       | 对账单发起对账               | 按主键匹配最早记录占用，或新增追加记录（详见第四节）                         |

### 三、单据更新触发

**触发时机**：单据表某单据的费用项成本更新后（含币种）。

**处理步骤**：

1. **数据合并**：从单据表查询该单据的所有费用项成本数据，按 `供应商编码 + 系统ID + 费用项 + 币种` 合并（金额累加），生成合并后的成本数据集合。
2. **检索**：按 `系统ID` 在底表中查找该单据下的所有记录。
3. **逐笔处理**（对合并后的每个 `费用项 + 币种` 组合）：
   - 按 `供应商编码 + 系统ID + 费用项 + 币种` 在底表精确查找，**取最早创建的那条**：
     - **找到** → 更新 `最新计算金额`（**无论明细状态如何都更新**），同步刷新以下字段：
       - `单据时间`：无论明细状态如何都刷新（单据创建初期可能仅有创建时间，后续各时间节点补齐后取值会变化，见字段定义L24）
       - `账单类型`：仅明细状态=空时刷新；明细状态≠空（系统对比中/待处理/已处理/已变更待复核/已完成）时保持不变
       - `供应商编码`、`供应商名称`：为查找主键组成部分，本分支不涉及刷新；若发生供应商变更，由"未找到→新增"+"删除多余记录"路径自然承接，详见第九节
     - **未找到** → 新增记录，写入 `最新计算金额`、`供应商编码`、`供应商名称`、`账单类型`、`单据时间`
4. **删除多余记录**：底表中存在、但本次合并结果中不存在的 `费用项 + 币种` 组合 → 取该主键下最早创建的那条：
   - 若 `明细状态` = 空 → **删除**
   - 若 `明细状态` ≠ 空 → **保留**（不删除）

> 说明：`最新计算金额` 永远实时更新；`明细状态` ≠ 空的记录受保护不可删除，且`账单类型`不随单据更新刷新（`最新计算金额`和`单据时间`除外，仍实时刷新）。

**合并示例**（同一费用项多因子拆分）：

| 单据表原始数据                   | 合并后数据           |
| -------------------------------- | -------------------- |
| YD001-清关费-CNY=100（按包裹数） | YD001-清关费-CNY=350 |
| YD001-清关费-CNY=200（按运单数） |                      |
| YD001-清关费-CNY=50（按核重）    |                      |

### 四、开始对账触发

**触发时机**：开始对账时，对账单中的每条明细逐一处理。

**处理步骤**：

1. **校验**：按 `对账单的供应商编码 + 系统ID + 费用项 + 币种` 在底表查找同主键下**所有记录**：
   - 存在任意记录 `明细状态` 非空且 ≠ 已完成 → **拦截**："该费用项存在未完成对账的占用（对账单XXX），请先完成对账"
   - 所有记录 `明细状态` = 空或 = 已完成 → 继续下一步
2. **匹配与写入**：按 `对账单的供应商编码 + 系统ID + 费用项 + 币种` 取**最早创建**的那条，按匹配结果执行：

| 匹配结果                                   | 操作                                                                                                                                                                                                                                            |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 找到，`明细状态` = 空                      | **占用**该记录：写入 `对账单ID`、`对账单明细ID`、`关联ID`、`关联类型`、`账单金额`、`明细状态`=系统对比中、`作废标记`=正常、`账单明细对比参数`；按**快照截取规则**，从本记录`最新计算金额`截取`快照计算金额`。若 `供应商编码/名称`、`账单类型`、`单据时间` 为空，从运单补写                                |
| 找到，`明细状态` = 已完成（追加场景）     | **新增**追加记录：写入 `对账单ID`、`对账单明细ID`、`关联ID`、`关联类型`、`币种`、`账单金额`、`明细状态`=系统对比中、`作废标记`=正常、`账单明细对比参数`；`最新计算金额`=空（主键唯一原则）；`快照计算金额`按**快照截取规则**截取——本记录无`最新计算金额`，截得为空；`供应商编码/名称`、`账单类型`、`单据时间` 按各字段的取数规则写入 |
| 未找到（主键下无任何记录）                 | **新增**记录：同上（该记录即主键下最早记录，待单据更新写入最新计算金额后承接成本角色）                                                                                                                                                          |

3. **差异类型判定**：底表写入完成后，按队列逐记录执行差异类型判定逻辑——综合本条记录的 `账单金额`、`快照计算金额`、单据/费用状态、是否重复/历史已对账、币种一致性等多维度判定（非单纯金额比对；尾程场景另需结合重量、计费重等参数）；`结算策略` 由会计自主确认。

> 追加记录快照为空的业务语义：该主键的成本已对过一次账，追加账单没有成本可对比，会计关注点是在"已付过"的背景下决定继续（确认）还是结束（终止）。

> **供应商隔离规则**：账单对账时，使用**对账单的供应商**匹配底表。若底表存在相同系统ID+费用项+币种但供应商不同的记录，**不占用原供应商的记录**，而是按对账单的供应商新建记录。这确保不同供应商的同系统ID+费用项+币种数据完全隔离。

> **孤儿账单**：系统ID为空时，按主键匹配底表（系统ID作为主键组成部分之一，取值为空）；匹配不到则新建记录，差异类型判定为"成本系统无单据"。

### 五、重新对比时的底表处理逻辑

**触发来源**：对账单明细页「重新对比无结算策略明细」按钮，仅对 `结算策略` 为空 + 未作废的明细生效。

**处理逻辑**：

1. **明细状态退回**：参与明细的 `明细状态` 先退回 `系统对比中`
2. **重截快照**：按**快照截取规则**，从本记录`最新计算金额`重新截取`快照计算金额`
3. **重跑差异类型判定**：按差异类型判定逻辑重新判定
4. **状态更新**：跑完按结果更新 `明细状态`：
   - 差异类型变化 → `已变更待复核`
   - 差异类型未变 → `待处理`
5. 已确认 `结算策略` 的明细（`明细状态`=已处理）不受影响

> 异步执行：重新对比采用异步执行，短时间内多次触发合并为1次；失败回滚恢复到退回前状态。

### 六、完成对账后处理

**触发时机**：完成对账时（对账单状态→已完成）。

**匹配维度**：按 `对账单明细ID` 精确匹配（底表记录与账单明细一一对应）。

**处理步骤**：遍历账单明细，逐条按 `对账单明细ID` 匹配底表记录，按**作废标记**分流处理：

#### 有效明细（作废标记=正常）

更新确认信息：

| 更新字段       | 取值来源                                                     |
| -------------- | ------------------------------------------------------------ |
| `账单金额`     | 当前账单明细的金额                                           |
| `差异类型`     | 按差异类型判定逻辑重新生成（多维度综合判定）；**清账除外**——清账流程开始对账时跳过差异判定、不生成账单明细对比参数，完成对账时固定写入「清账」 |
| `结算策略`     | 回写会计在对账中填选的结算策略值（完成对账校验要求全部明细已绑定结算策略） |
| `付款金额`     | 当前账单明细的付款金额                                       |
| `完成对账时间` | 完成对账操作的系统时间（精确到秒），写入后作为静态值不再变更 |
| `明细状态`     | 更新为已完成                                                 |

#### 作废明细（作废标记=作废）

**释放原占用记录R** + **新增作废追加记录R'**：

**① 释放原记录R**（回池，可被新账单占用）：

| 字段 | 处理 |
|------|------|
| `对账单ID` | 清空 |
| `对账单明细ID` | 清空 |
| `明细状态` | 置空（=未占用） |
| `账单金额` | 清空 |
| `快照计算金额` | 清空 |
| `差异类型` | 清空 |
| `结算策略` | 清空 |
| `付款金额` | 清空 |
| `关联ID` | 清空 |
| `关联类型` | 清空 |
| `作废标记` | **置正常**（恢复为正常，回池可被统计与新账单占用） |
| `最新计算金额` | **保留**（仍由单据表实时同步） |
| `供应商`、`账单类型`、`单据时间` | 保留 |

**② 新增作废追加记录R'**（仅用于底表查询追溯，不参与统计/清账/计提）：

| 字段 | 值 |
|------|-----|
| `对账单ID` | 原对账单ID（保留归属） |
| `对账单明细ID` | 原对账单明细ID（保留归属） |
| `关联ID` | 原关联ID（保留归属） |
| `关联类型` | 原关联类型（保留归属） |
| `明细状态` | 已完成 |
| `作废标记` | 作废 |
| `账单金额` | 原账单金额（保留原始值） |
| `最新计算金额` | 空（主键唯一原则） |
| `快照计算金额` | 空 |
| `差异类型` | 空 |
| `结算策略` | 空 |
| `付款金额` | 空 |
| `完成对账时间` | 完成对账操作的系统时间（与有效明细取同一值） |
| 其他字段 | 按主键规则写入 |

> **过滤规则**：所有统计/清账/计提模块统一**排除作废追加记录 R'**（即排除 `作废标记 = 作废` 且 `明细状态 = 已完成` 的记录）。
>
> 说明：作废标记为"作废"但明细状态非"已完成"的记录（即对账中阶段被标记作废的 R，明细状态保持原值如已处理）**仍参与底表统计**——其计算成本应被纳入"未结算"统计，避免对账期间作废导致成本数据"消失"；完成对账时 R 被释放回池（作废标记置正常、明细状态置空），自然转入"未结算"统计；同时新增的 R'（作废标记=作废、明细状态=已完成）仅用于追溯，被排除。

### 七、对账单取消后处理

**触发时机**：取消对账（明细解除绑定）。一张账单内同一主键只有一条记录，逐主键独立处理，无批量顺序问题。

**处理逻辑**：按 `对账单ID` 检索关联记录，按**记录身份**分流：

| 记录身份                        | 操作                                                                                                                                                                                             |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 后创建的追加记录                           | **直接删除**                                                                                                                                                                                     |
| 最早创建的记录   | **纯解绑**：清空 `对账单ID`、`对账单明细ID`、`明细状态`（置空）、`账单金额`、`快照计算金额`、`差异类型`、`结算策略`、`付款金额`、`作废标记`（置正常）、`账单明细对比参数`、`关联ID`、`关联类型`，**保留记录**；`最新计算金额`、`供应商`、`账单类型`、`单据时间` 保留原值 |

> 补充：取消对账后，本条记录若 `账单金额` 和 `最新计算金额` 均为空，则失去存在意义，删除；若有成本无账单，则保留。

> **归位合并已取消**：开始对账校验机制（见第四节）确保同一主键下不会出现"前一份对账单未完成时后一份对账单开始对账"的场景，因此取消对账时不存在"同主键下仍有其他占用记录"的归位合并需求。

### 八、供应商变更场景

> 本节为第三节单据更新流程在"供应商变更"场景下的结果性说明，与第三节通用流程（"未找到→新增"+"删除多余记录"）完全一致，非独立实现逻辑。

**触发条件**：单据同步时供应商发生变更（原供应商A → 新供应商B），即同一系统ID+费用项+币种下，文档表的供应商从A改为B。

**处理逻辑**：

1. **原供应商A维度**：文档表不再有供应商A的成本记录，底表对应记录的`最新计算金额`被清空。若该记录`账单金额`和`最新计算金额`均为空，按"失去存在意义"规则删除；若仍被账单占用（`明细状态`≠空），则保留记录但`最新计算金额`为空
2. **新供应商B维度**：追加记录从文档同步获得`最新计算金额`，自然承接成本承载角色（成为该供应商维度下最早的记录）
3. **快照计算金额**：保持原状（不立即更新），待财务手动触发重新对比时再重截快照并重跑差异判定

> 示例：系统ID=WD001+运费+HKD，原供应商A成本=100已占用（R1明细状态=已处理），账单供应商B新建追加记录R2（快照空）。单据同步供应商改为B、成本=120 → R1清空删除，R2从文档同步获得`最新计算金额=120`，快照保持空，待重新对比时更新。
