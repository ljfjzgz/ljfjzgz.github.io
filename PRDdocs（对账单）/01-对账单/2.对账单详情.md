## 二、操作区

一组操作按钮置于「三、金额汇总」标题栏右侧，按状态控制显隐。

### 2.1 状态操作按钮

按钮随对账单「状态」动态切换：

| 状态   | 显示按钮              | 说明                                                                                                                                                                                                                                                                                                            |
| :----- | :-------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 草稿   | `无`                  | 草稿态的推进由基础信息区完成：基础信息区右下角显示「编辑」按钮，点击→进入编辑模式，可编辑字段显示输入控件、标准账单显示覆盖上传入口，同时出现「取消」「保存」按钮；点击「取消」放弃编辑退回只读；点击「保存」保存编辑内容并直接推进至待对账。操作区（标题栏右侧）不单独提供「保存并推进至待对账」按钮 |
| 待对账 | `开始对账`            | 二次确认（提示将占用底表记录、截取快照并跑差异判定），确认后 → 对账中                                                                                                                                                                                                                                           |
| 对账中 | `取消对账` `完成对账` | 见下方动作说明                                                                                                                                                                                                                                                                                                  |
| 已完成 | 无                    | 终态，仅展示结果                                                                                                                                                                                                                                                                                                |

**动作说明**：

- **完成对账**：不可逆终态；二次确认，确认前系统校验——至少有一条有效明细（作废标记=正常），且所有有效明细均已绑定结算策略；校验不通过时阻断并提示对应问题。校验通过后回写底表并生成账单管理数据，推进至已完成。
- **取消对账**：二次确认，提示"将释放底表占用、清除快照计算金额、**清空结算策略、作废标记置正常**，回到待对账"；采用软取消——释放底表占用与快照，**保留**对账单头与明细行结构，回到待对账可直接重开对账。

### 2.2 下载对账结果汇总

- **位置**：操作区最右侧，与状态操作按钮同行。
- **功能**：点击下载该对账单完整的金额汇总与分析数据Excel文件。
- **触发条件**：开始对账后即可下载（草稿/待对账状态下按钮置灰或隐藏；对账中及已完成状态下可用）。
- **数据范围**：按结算策略 + 差异类型 + 费用项分组的金额汇总行（账单金额、快照计算金额、计算差异、付款金额等）。

### 2.3 完成对账提示场景

点击「完成对账」（对账中 → 已完成）时，系统先执行前置校验，再弹出二次确认；执行结果为原子事务（只有"全部成功"或"全部失败回滚"两种终态）。

**校验对象统一为有效明细（作废标记 = 正常）；作废明细全程不计入本单校验与本单汇总（底表全量统计模块对R另有口径，详见对账明细底表过滤规则）。**

#### 2.3.1 前置校验（校验不通过则阻断，不弹二次确认）

| 场景             | 触发条件                                                                              | 提示文案                                                           | 类型 |
| :--------------- | :------------------------------------------------------------------------------------ | :----------------------------------------------------------------- | :--- |
| A 无有效明细     | 有效明细数量 = 0（含：对账单无任何明细记录 / 明细全部已作废）                         | 「当前对账单无有效明细（明细均已作废或无明细数据），无法完成对账」 | 阻断 |
| B 有效明细缺策略 | 有效明细中存在 `结算策略` 为空的记录（枚举 7 种含"清账"均视为已绑定；作废明细不计入） | 「存在未指定结算策略的明细，请先处理」                             | 阻断 |

#### 2.3.2 二次确认弹窗（A、B 均通过后弹出）

**主文案**：

> 确认完成对账？完成后将：
> ① 回写**有效明细**的底表占用并生成账单管理数据；
> ② 批量释放**作废明细**占用的底表记录（原占用记录R回池可被新账单占用；同时新增作废追加记录R'，仅用于追溯不计入统计）；
> ③ 状态置为「已完成」且不可再反结账。
> 确认继续？

**动态附加行**（按需显示）：

- 存在 N 条作废明细 → 追加「本次将释放 N 条作废明细占用的底表记录」
- 作废明细中存在未填结算策略的 → 追加「有 N 条作废明细未指定结算策略，因其不参与对账将直接释放，不影响完成」（非阻断告知）

#### 2.3.3 执行与结果（原子操作）

- **全部成功**：回写有效明细底表占用 + 生成账单管理数据 + 释放作废明细占用，状态置「已完成」 → 提示「完成对账成功，已生成账单管理数据（账单管理ID：xxx）」
- **任一失败**：整体回滚至「对账中」（底表回写、作废占用释放均撤销，状态保持对账中） → 提示「完成对账失败：xxx，已回滚至对账中，请重试或联系管理员」
- **核心约束**：完成对账为原子事务，**只有"全部成功"或"全部失败回滚"两种终态，不存在部分成功**。

## 三、金额汇总

按**账单类型**汇总该账单的逐条明细数据，便于从整体上查看对账差异。不同币种分开展示，不合并汇总。

### 字段说明

| 字段         | 说明                    | 取值逻辑                                                         |
| :----------- | :---------------------- | :--------------------------------------------------------------- |
| 账单类型     | 按账单类型分组          | 取逐条明细的账单类型                                             |
| 币种         | 该分组的金额币种        | 取自逐条明细的币种，同一账单类型下币种唯一（不同币种拆分行展示） |
| 账单金额     | 该类型账单金额合计      | 汇总逐条明细的账单金额                                           |
| 快照计算金额 | 系统快照计算金额合计    | 汇总逐条明细的快照计算金额                                       |
| 计算差异     | 账单金额 − 快照计算金额 | 账单金额 − 快照计算金额                                          |
| 付款金额     | 该类型付款金额合计      | 汇总逐条明细的付款金额                                           |
| 付款差异     | 账单金额 − 付款金额     | 账单金额 − 付款金额                                              |
| 处理明细     | 查看该类型逐条明细入口  | 点击跳转至对账明细（按当前账单类型 + 币种过滤）              |

### 示例

以下展示该对账单的金额汇总示例：

| 账单类型 | 币种 | 账单金额 | 快照计算金额 | 计算差异 | 付款金额 | 付款差异 | 处理明细 |
| :------- | :--- | :------- | :----------- | :------- | :------- | :------- | :------- |
| 尾程派送 | CNY  | 1,530.00 | 1,394.30     | 135.70   | 1,530.00 | 0.00     | 处理明细 |

## 四、处理文件

本模块用于**批量更新对账明细的结算策略和作废标记**，位于对账单详情页内。

### 4.1 操作区

| 元素     | 说明                                                                                          |
| :------- | :-------------------------------------------------------------------------------------------- |
| 文件模版 | 蓝色链接文字，点击下载预设 Excel 导入模版（表头：明细ID、结算策略、作废标记）                 |
| 选择文件 | 按钮，弹出系统文件选择器，仅支持 `.xlsx` 格式；选中后按钮旁回显文件名（默认"未选择任何文件"） |
| 提交文件 | 按钮，上传已选文件；触发导入后表格新增一行，状态置为「待执行」，随后自动进入队列执行          |

> **格式说明**：处理文件模版采用 Excel 格式，结算策略列填1-6或留空（留空=清空策略），作废标记列填"正常"或"作废"。

### 4.2 表格列字段

| 列名     | 说明                                                                                  |
| :------- | :------------------------------------------------------------------------------------ |
| Id       | 文件唯一标识                                                                          |
| 状态     | 处理状态：`待执行` / `执行中` / `执行完成` / `执行失败`                               |
| 源文件   | 原始文件名，点击文件名可下载                                                          |
| 导入人   | 操作人姓名                                                                            |
| 导入时间 | 文件上传时间                                                                          |
| 处理消息 | 执行完成时显示「批量修改成功，共处理X条明细」；执行失败时显示「下载校验结果文件」链接 |

示例：

| Id  | 状态     | 源文件                                  | 导入人 | 导入时间         | 处理消息                          |
| :-- | :------- | :-------------------------------------- | :----- | :--------------- | :-------------------------------- |
| 1   | 执行完成 | 结算策略修改\_20260805.xlsx（点击下载） | dev    | 2026-08-05 10:24 | 批量修改成功，共处理12条明细      |
| 2   | 执行失败 | 结算策略修改\_20260805.xlsx（点击下载） | dev    | 2026-08-05 11:02 | 下载校验结果文件（共3条校验失败） |

### 4.3 交互逻辑

1. **下载模板**：点击「文件模板」→ 下载空白Excel模板，包含表头：明细ID、结算策略、作废标记。
2. **线下编辑**：用户填写明细ID、结算策略（填1-6或留空=清空策略）、作废标记（填"正常"或"作废"）。
3. **提交校验**（逐行全部校验，不提前阻断，校验完后判定结果）：

| 校验项     | 规则                                                                                                                            | 失败提示（写入校验结果文件）                                     |
| :--------- | :------------------------------------------------------------------------------------------------------------------------------ | :--------------------------------------------------------------- |
| 对账单状态 | 必须为「对账中」                                                                                                                | 整文件阻断：「仅对账中状态可导入修改文件，当前状态：[实际状态]」 |
| 明细ID     | 必须存在且属于当前对账单                                                                                                        | 第N行：「明细ID不存在或不属于当前对账单」                        |
| 结算策略   | 必须为空或1-6，不可填清账(7)                                                                                                    | 第N行：「结算策略值无效，须为空或1-6」                           |
| 作废标记   | 必须为"正常"或"作废"                                                                                                            | 第N行：「作废标记值无效，须为"正常"或"作废"」                    |
| 明细状态   | 变更作废标记的明细，其`明细状态`必须≠「系统对比中」（系统正在处理，避免冲突）                                                  | 第N行：「明细[明细ID]处于系统对比中状态，不可变更作废标记」      |
| 业务规则   | 系统取该明细的实际差异类型——若差异类型=「对账币种不一致」，则结算策略不可为3（按系统金额支付+争议）或4（按系统金额支付+不争议） | 第N行：「差异类型为对账币种不一致，不可选按系统金额支付结算策略」    |

4. **执行更新**：全部行校验通过后方可执行，联动规则：
   - 付款金额：按结算策略自动带出——按账单金额支付取币种+账单金额；按系统金额支付取币种+快照计算金额；不支付/清账取币种+0；策略为空则付款金额全空
   - 明细状态：设非空策略→已处理；清空策略→待处理；仅作废标记变更时明细状态保持当前处理进度
5. **结果反馈**：
   - 全部校验通过：状态置「执行完成」，处理消息显示「批量修改成功，共处理X条明细」
   - 存在校验失败：状态置「执行失败」，处理消息显示「下载校验结果文件」链接。校验结果文件包含**全部行**数据，每行标注「校验通过」或具体失败原因，方便用户一次性修正所有问题后重新提交
6. **多次导入**：同一明细ID允许多次导入，以**最后一次提交**为准。

## 五、日志与备注

页面顶部以 Tab 切换展示，分为「日志」与「备注」两个标签页：

- **日志**：展示系统**自动记录**的操作轨迹（如创建、状态变更、文件导入等），由系统在事件触发时自动写入，用于审计追溯与操作留痕。
- **备注**：展示人工**手动添加**的跟进记录，便于多人协作时同步处理进展与上下文。

### 5.1 日志（系统自动记录）

| 字段   | 说明                           | 示例                         |
| :----- | :----------------------------- | :--------------------------- |
| 时间   | 操作发生的精确时间（精确到秒） | 2026-07-31 13:59:02          |
| 操作人 | 触发操作的账号 / 姓名          | dev                          |
| 操作   | 操作类型                       | 创建 / 状态变更 / 导入文件   |
| 描述   | 本次操作的补充说明             | 由「待对账」变更为「对账中」 |
| IP     | 操作来源 IP                    | 192.168.1.10                 |
| 环境   | 操作所在环境                   | 生产 / 测试                  |

**记录范围（触发时机）**：创建对账单、状态变更（开始对账 / 取消对账 / 完成对账）、处理文件导入、账单生成回写等。日志只读。

### 5.2 备注（人工跟进记录）

#### 5.2.1 输入区（列表上方）

- **文本输入框**：占位提示「添加备注」，支持多行输入，最大长度 500 字。
- **提交按钮**：文案「提交」；点击后以当前登录人身份将输入内容写入备注列表，并清空输入框。
- **校验规则**：内容为空时禁用提交。

#### 5.2.2 备注列表（输入区下方）

以表格形式展示，每行一条记录，按添加时间**倒序**（最新在上）排列。

| 字段     | 说明              | 示例                |
| :------- | :---------------- | :------------------ |
| 添加人   | 操作人账号 / 姓名 | dev                 |
| 备注内容 | 输入的文本内容    | 111（或一段文字）   |
| 添加时间 | 精确到秒的时间戳  | 2026-07-31 13:59:02 |

#### 5.2.3 交互与规则

- 列表仅展示**当前对账单**下的备注；与「一、基础信息」中的「备注」字段呼应（该字段展示条数 / 最新摘要）。
- 备注一经提交**不可编辑/删除**，保留完整跟进历史，便于责任追溯。
- 添加人取当前登录账号，确保跟进记录可定位到具体责任人。
