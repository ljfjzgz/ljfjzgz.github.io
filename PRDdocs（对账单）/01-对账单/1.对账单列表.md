## 三、状态说明

列表「状态」取值（来自账单处理流程）：

| 状态   | 含义                                                                              | 流转                                                         |
| :----- | :-------------------------------------------------------------------------------- | :----------------------------------------------------------- |
| 草稿   | 已导入，待编辑确认后推进                                                          | 编辑确认 → 待对账                                            |
| 待对账 | 已确认，待「开始对账」                                                            | 「开始对账」→ 对账中                                         |
| 对账中 | 已「开始对账」：底表记录占用 + 差异判定完成，可逐条处理 / 重新对比，尚未完成对账  | 执行「完成对账」→ 已完成；「取消对账」→ 待对账               |
| 已完成 | 执行「完成对账」后终态：对账明细底表回写完成对账信息、已生成账单管理数据 | 不可逆（调整走业务冲销） |

> 流转说明：
>
> - **草稿 → 待对账**：用户在详情页基础信息区编辑后点击「保存」手动推进；导入仅落账单明细，不写底表。
> - **待对账 → 对账中**：在明细页点「开始对账」，系统按 `供应商编码+系统ID+费用项+币种` 匹配成本、占用底表记录、截取快照计算金额并跑差异判定。
> - **对账中（可停留）**：支持逐条「重新对比」（归位合并检查 + 重截快照 + 重跑差异），仅对**结算策略为空且未作废**的明细重跑，已确认结算策略的明细跳过；状态保持对账中不变。归位合并通常在取消对账时已同步完成，重新对比时检查无待归位记录则跳过。
> - **对账中 → 已完成**：执行「完成对账」，校验通过后回写底表、生成账单管理数据；为终态不可逆。**前置校验**：对账单下存在「系统对比中」状态的明细时不可完成对账（需等待系统处理完成转为「待处理」等状态后方可）。
> - **对账中 → 待对账（取消对账）**：执行「取消对账」，释放底表记录占用、清除快照计算金额、**清空结算策略**，回到待对账；采用软取消——保留对账单头与明细行结构，可直接重开对账。

> 注：账单生成状态（是否已生成账单管理数据）由独立的「是否生成账单」字段记录，不归入上述工作流状态；其取值与 `账单管理ID` 回写由系统自动处理。

## 四、列表操作

| 操作         | 入口 / 适用                         | 说明                                   |
| :----------- | :---------------------------------- | :------------------------------------- |
| 导入对账单   | 列表页按钮，弹窗操作                | 上传供应商账单文件，生成草稿对账单     |
| 进入明细     | 点击行内 ID                         | 进入对账单详情查看与处理明细           |
| 删除         | 批量，适用草稿/待对账态             | 删除未进入正式处理流程的账单           |
| 重新生成     | 批量，适用「已完成且是否生成账单=否」 | 对已完成但未生成账单管理数据的对账单，重新触发账单管理数据生成 |

### 4.1 导入对账单

在列表页通过「导入对账单」按钮（弹窗）提交供应商账单文件，生成一条对账单草稿数据，随后在下方列表继续后续处理。

**页面字段**：

| 字段     | 说明                                                       | 必填 |
| :------- | :--------------------------------------------------------- | :--- |
| 供应商   | 下拉选择已维护供应商（如 SHAOKE / DHL_ECOMMERCE / TAIJIA） | 是   |
| 账单文件 | 上传供应商原始账单文件                                     | 是   |

> 仅两个输入项，无其余表单字段；「确认」即弹窗中的「保存」按钮。

**操作步骤**：

1. 点击列表页「导入对账单」按钮，打开导入弹窗；
2. 选择**供应商**；
3. 点击「选择文件」上传**账单文件**；
4. 点击「确认」，系统解析账单文件、在下方列表**生成一条对账单数据**（初始为**草稿**状态）；**导入仅落账单明细数据，不写入对账明细底表**——底表的匹配与占用在详情页「开始对账」时才执行。

### 4.2 重新生成账单管理数据

**适用条件**：对账单状态=已完成 且 是否生成账单=否。

> 业务场景：完成对账时账单管理数据生成失败或未触发，需补生成。已完成为终态，此操作仅补生成账单管理数据，不回退对账状态。

**操作流程**：

1. 勾选目标对账单（支持单条或批量）；
2. 点击「重新生成」；
3. 系统校验：勾选记录必须全部满足「已完成且是否生成账单=否」，否则阻断并提示「重新生成仅适用「已完成且是否生成账单=否」的对账单，请取消勾选不符合的记录」；
4. 校验通过后二次确认「确认重新生成选中的 N 条对账单的账单管理数据？」；
5. 确认后系统按完成对账时的规则重新生成账单管理数据（1:1生成、按付款金额取数），生成成功后回写账单管理ID、是否生成账单置为「是」。

**异常处理**：重新生成为原子事务，任一失败则整体回滚，是否生成账单维持「否」，状态保持「已完成」，用户可重新提交。
