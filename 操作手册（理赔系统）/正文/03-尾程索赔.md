# 03 尾程索赔

本章按单据生命周期讲尾程索赔线的六件事：**录单 → 查单 → 审核 → 改错 → 回填确认 → 红冲**。

尾程为订单维度（一个订单一条索赔记录），**不需要分摊**，且与干线不同：支持批量审核、批量红冲，也支持导入。字段定义见附录 B.3。

---

## 4.1 让索赔数据进来

### 4.1.1 批量导入尾程索赔

**什么时候做**：有一批尾程索赔数据需要入系统。

**在哪做**：数据导入 → 尾程索赔导入。该菜单下「直接上传」「队列上传」两个入口**页面完全相同**，仅提交后是否等待结果不同（同步 / 异步 的完整说明见 01 §2.1.1）；队列任务的结果到上传队列页看（见 4.1.2）。

进入页面后，「操作类型」选择**新增尾程索赔**（同一页面另有「批量确认金额」，见 4.5.2）。

**怎么做**：按模板填写后上传 .xlsx（不超过 10MB）：

| 模板列 | 必填 | 填写要求 |
| --- | --- | --- |
| 处理号 | 是 | 须在 OMS 订单表中存在 |
| 索赔原因 | 是 | 须在索赔原因（供应商）配置表中存在（维护见附录 A） |
| 索赔币种 | 是 | 标准币种代码 |
| 索赔金额 | 是 | 大于 0，最多 2 位小数 |
| 索赔标准 | 否 | 最多 100 字符 |
| 备注 | 否 | 最多 200 字符 |

**唯一性校验**（按「处理号 + 索赔原因」查未红冲记录）：

| 情况 | 结果 |
| --- | --- |
| 记录存在（未红冲） | 阻断：「处理号【X】已存在索赔原因【Y】的未完结索赔记录，请勿重复导入。如需重新索赔，请先红冲原索赔单。」 |
| 记录不存在 | 允许导入 |
| 记录存在但已红冲 | 允许导入 |

**做完会怎样**（直接上传；队列上传见 4.1.2）：通过校验的数据创建为【待审核】；系统根据处理号自动带出产品代码、渠道代码、目的国；显示导入结果汇总，可下载失败提示文档，文档在原上传表数据基础上增加一列「失败原因」，逐行说明失败原因。

**注意**：导入是**逐行校验、部分成功**——通过的行直接建单，失败的行不影响其他行，不存在「整份回滚」。「成功 X / 失败 Y」是正常结果，要处理的是失败文档里的那几行。

### 4.1.2 上传队列：看异步导入的进度与结果

**什么时候做**：用「队列上传」提交过导入，需要知道这批跑到哪一步、成功多少条、哪些行失败。

**在哪做**：数据导入 → 上传队列。**赔付客户导入与尾程索赔导入共用这一页**，两条业务线的队列任务都汇总在这里；页面只显示当前用户自己上传的任务。

**怎么看**：

筛选条件：上传时间（按范围选）、文件名关键字、批次号（系统生成）、状态、类型。

列表按任务一行，其中几列需要知道：

| 列 | 含义 |
| --- | --- |
| 类型 | 这次任务是哪条业务线的哪种操作，如「尾程索赔-新增索赔」「尾程索赔-批量确认金额」 |
| 文件ID | 点「下载原文件」可把那一次上传的 Excel 原样下回来 |
| 总条数 / 完成条数 / 失败条数 | 文件里的行数，以及其中建单成功、校验未通过的行数；失败条数为红色数字，点击可下载失败文件，文件在原上传表数据基础上增加一列「失败原因」，说明该行为什么失败 |

**任务怎么跑起来**：队列上传提交后自动执行，不需要人工启动。

**注意**：失败条数大于 0，说明这批数据是**逐行校验、部分成功**——已建单的部分不用管，要处理的是失败的那些行。

### 4.1.3 单条新增索赔

**在哪做**：列表顶部【新增】。

**怎么做**：选择处理号后系统自动带出产品代码、渠道代码、目的国；填写索赔原因、索赔标准、索赔金额（币种 + 金额）、备注；提交时执行全字段校验。

**做完会怎样**：创建为【待审核】，返回列表并提示新增成功。

---

## 4.2 找到要处理的单子：查询、筛选与导出

**在哪做**：尾程索赔列表页。

**怎么做**：列表支持按以下字段筛选（字段含义见附录 B.3）：处理号（支持批量查询）、产品代码、渠道代码、目的国、索赔类型、索赔原因、索赔状态、审核时间、确认时间、创建时间、完结时间、单据类型。

**做完会怎样**：

- 列表上方实时显示当前查询条件下的**索赔原币汇总**（分币种，不折算 CNY，不随翻页变化）；
- 点【导出】下载当前筛选结果。

**注意**：本页的【批量审核】【批量红冲】作用于**查询条件命中的全部记录**（不是勾选项），操作前先核对汇总条数与预期。

---

## 4.3 审核索赔

### 4.3.1 单条审核

**什么时候做**：索赔状态为【待审核】。

**怎么做**：弹窗只读展示处理号、产品代码、渠道代码、目的国、索赔金额；填写审核结果（通过/驳回）与审核意见（驳回时必填，至少 5 个字符）。

**做完会怎样**：通过 → 【索赔中】，记录审核时间与审核人；驳回 → 【已驳回】，可编辑后重新提交。审核通过时**不写底表**，底表于回填确认后写入。

### 4.3.2 批量审核

**在哪做**：列表顶部【批量审核】。

**怎么做**：先设查询条件（条件即作用范围）；系统逐条校验**当前筛选结果须全部为【待审核】**，否则阻断并提示「当前筛选条件下存在 N 条非待审核的记录，汇总数与实际可审核数不一致。请确认查询条件后重新操作。」；全部通过后弹窗展示记录数、条件摘要与审核结果选择，确认后批量执行（逻辑同单条）。

---

## 4.4 录错了怎么办：编辑与删除

**什么时候做**：状态为【待审核】或【已驳回】。

**在哪做**：列表行内【编辑】/【删除】。

**做完会怎样**：编辑保存后状态重置为【待审核】，需重新审核——哪怕只改一个字段也一样；删除为物理删除（二次确认）。已完结、索赔中，以及红冲索赔单，不提供编辑入口。

---

## 4.5 回填确认金额

### 4.5.1 单条回填确认

**什么时候做**：索赔状态为【索赔中】且确认金额为空。

**怎么做**：

| 字段 | 必填 | 要求 |
| --- | --- | --- |
| 确认币种 | 是 | 须与原索赔币种一致 |
| 确认金额 | 是 | ≥ 0 且 ≤ 索赔金额，最多 2 位小数 |
| 确认汇率 / 确认金额 CNY | — | 系统按审核通过时汇率自动带出与计算 |
| 确认备注 | 否 | 最多 200 字符 |

阻断规则：「确认金额【A】大于原索赔金额【B】，请核实」；「已有确认金额【A】，不可重复确认」。

**做完会怎样**：状态直接变更为【已完结】，记录确认人、确认时间、完结时间；系统将索赔金额 CNY 与确认金额 CNY 写入底表并刷新索赔确认差异 CNY（尾程无需分摊）。

### 4.5.2 批量确认金额导入

**什么时候做**：供应商集中确认了一批索赔，需要一次回填。

**在哪做**：数据导入 → 尾程索赔导入 → 直接上传或队列上传（入口差异见 4.1.1），「操作类型」选择**批量确认金额**。

**怎么做**：按模板填写后上传：

| 模板列 | 必填 | 要求 |
| --- | --- | --- |
| 处理号 | 是 | 须在 OMS 订单表中存在 |
| 索赔原因 | 是 | 须在配置表中存在，与处理号组成匹配键 |
| 确认金额原币 | 是 | ≥ 0 且 ≤ 索赔金额 |
| 确认币种 | 是 | 须与原索赔币种一致 |
| 确认备注 | 否 | — |

逐行校验，任一不满足即该行失败：

| 校验项 | 不通过时 |
| --- | --- |
| 索赔状态 = 索赔中 | 该记录不是【索赔中】，该行失败 |
| 红冲单号为空 | 该记录已红冲，该行失败 |
| 确认金额为空 | 该记录已有确认金额，该行失败 |
| 确认金额 ≥ 0 | 确认金额为负数，该行失败 |
| 确认金额 ≤ 索赔金额 | 确认金额大于索赔金额，该行失败 |
| 确认币种 = 索赔币种 | 确认币种与索赔币种不一致，该行失败 |

**做完会怎样**（直接上传；队列上传见 4.1.2）：通过的行执行与单条回填确认相同的动作（记录确认信息、状态转为【已完结】、写入底表）；显示成功 X 条 / 失败 Y 条，可下载失败提示文档，文档在原上传表数据基础上增加一列「失败原因」，逐行说明失败原因。

---

## 4.6 冲掉索赔：红冲

### 4.6.1 单条主动红冲

**什么时候做**：同时满足以下三条（任一不满足即阻断并提示）：

- 单据类型 = 正常索赔
- 红冲单号 = 空
- 索赔状态 = 已完结

**在哪做**：列表行内【红冲】，填写红冲说明后确认。

**做完会怎样**：

- 生成红冲单：处理号与原单一致，单据类型「红冲索赔」，金额取原单相反数，状态【待审核】；立即回填红冲单号到原索赔单；
- 红冲单审核通过：自动填入确认金额 = −(原单确认金额)，确认汇率复制原单；**复制原单索赔记录逐行取负写入底表（不再重新分摊）**，状态直接流转至【已完结】；
- 审核驳回则为【已驳回】，可删除后重新发起。

**注意**：红冲单号在**发起红冲的那一刻**就写回原索赔单，不等红冲单审核通过。因此红冲单被驳回时，原单已不能再次发起红冲，只能删除红冲单（清空红冲单号，见 4.6.3）或重新提交审核。

### 4.6.2 批量红冲

**在哪做**：列表顶部【批量红冲】。

**怎么做**：按下列顺序逐条校验，每条不合规记录只计入第一个命中项：

| 顺序 | 校验项 | 阻断提示 |
| --- | --- | --- |
| 1 | 单据类型 = 正常索赔 | 存在 N 条红冲索赔单据，无法批量红冲 |
| 2 | 红冲单号为空 | 存在 N 条已红冲的记录 |
| 3 | 索赔状态 = 已完结 | 存在 N 条非已完结状态的记录 |

弹窗列出所有 N>0 项及数量，任一项不通过即阻断；全部通过则确认后批量生成红冲单（无表单填写），完成后提示批量红冲成功。

### 4.6.3 删除红冲单

**什么时候做**：红冲单状态为【待审核】或【已驳回】。

**做完会怎样**：二次确认后物理删除，并清空原索赔单的红冲单号，原单可重新发起红冲；【索赔中】【已完结】不可删除。
